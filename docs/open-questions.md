# 未決事項・次のステップ

## 決定済み（2026-09-20）

詳細は `docs/architecture.md` を参照。

- 初回対象は**米国株**。SEC EDGAR + yfinance で完全無料。日本株は第一弾より後。
- 実行基盤：まずローカル CLI、安定後に K3s CronJob（クラスタ `yuxsr-dev` / ノード `pollux`、local PVC 利用）。
- ストレージ：DuckDB 単一ファイル（`data/stock_radar.duckdb`）。生の zip はファイルで保持。
- スタック：Python + uv。
- 出力：CSV + 通知。通知先は同一クラスタ内にデプロイ済みの自前アプリ `notificator`（Service 名で到達可能）。
- 会計期間：年次（10-K）主、売上のみ四半期（10-Q）も保持。
- ユニバース：金融・REIT 除外（SIC 6000番台）、ADR 除外（10-K 提出企業のみ）、売上ゼロ除外。
- トラックB の「予想売上成長率」は米国に会社予想が無いため、**直近四半期 YoY ≥ 20%** で代替。
- 「資産成長率 − EBITDA成長率」は減価償却費のタグ揺れが重いため、**EBIT（営業利益）で代用**。後から差し替え可能にする。
- 第一弾のスコープ：スクリーニング + CSV + 通知まで。Kill 条件監視とフィードバック記録は後回し。

### 評価スキルとの突き合わせで見つかった論点（2026-09-22）

2026-09-22 の run のうち、タイミング加点順で上から5件を評価スキルにかけたところ、5件とも総合6.5以下だった（#53）。
原因を追って見つかったのが次の2点。2026-09-23 にユーザーと決めた。

- [x] **③モート・⑤カタリスト（スコアの加重 0.30）に対応する足切りが無い**（#54）。
  **2026-09-23 決定：足切りは足さない。③は CSV に参考値 `gross_margin_change_3y` を載せ、⑤は扱わない。**
  根拠は `docs/skill-integration.md` の「評価スキルの5軸のうち、スクリーナーが見ていないもの」
  - 総合8.0に届くのは、事業側（①②③⑤の加重平均）が 7.15 以上の銘柄だけ
    （`0.3×10 + 0.7×7.143 = 8.0`）。MNTN・IRTC・TMDX の事業側は 6.3〜6.5 で、総合の上限は 7.4〜7.5
  - 粗利率の3年変化を −5pt で足切りにすると、落ちるのは TMDX だけ。ただしその低下は事業構成の変化によるものと見られる
  - RPO の出現率はユニバースの22.6%で、足切りにも参考列にも向かない
- [x] **トラックAの合格ラインが、評価スキルの①成長性では3〜4点の帯に落ちる**（#55）。
  **2026-09-23 決定：10%のまま据え置き、トラックA/B を分けて読む。** 根拠は `docs/screening-criteria.md` の②
  - トラックAの入口は `revenue_cagr_3y ≥ 10%`。`scorecard.md` の①では「成長10%未満」が3〜4点、
    「15〜25%」が5〜6点。加重0.20なので、トラックA候補はトラックB候補より構造的に0.6〜1.0点低く出る
  - 根っこは前提の違い。トラックAの根拠の Yartseva (2025) は成長率を有意でないとしてモデルから外している
    （`docs/screening-criteria.md`）。評価スキルは成長性に0.20を配分している
  - 選択肢：評価スキル側で①の扱いを変える（「加重は銘柄によって変えない」という `scorecard.md` の方針と衝突する）／
    トラックAの CAGR 下限を15%以上に上げる（Yartseva の知見を捨て、通過件数も減る）／
    何も変えず、トラックA候補は低く出るものとして読む／どちらの前提が実際のリターンに効いたかを検証する
  - 15%に上げると 2026-09-21 の run のトラックA 8件のうち1件しか残らない。どちらの前提が効くかの検証は
    フィードバック記録（`docs/skill-integration.md`）が始まってから

**どちらも足切りを変えない側に倒した。** 判断材料は5件分のスコアしかなく、選び方も52週安値に近い順だった
（銘柄の優劣で選んだ5件ではない）。候補20件前後に簡易評価をかけてトラックA/B 別の分布と③⑤の点数が取れたら、
あるいはフィードバック記録が始まったら見直す。
