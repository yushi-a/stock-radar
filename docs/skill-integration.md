# 評価スキル（growth-stock-evaluation）との役割分担

基本思想：スクリーナーは「広く・機械的に・漏らさない」、評価スキルは「深く・一次情報で・判断する」。

| | スクリーナー（本リポジトリ） | 評価スキル |
|---|---|---|
| 目的 | 取りこぼさない | 誤って選ばない |
| 対象 | 全銘柄 → 20〜30件 | 5〜10件 |
| 頻度 | 週次バッチ | オンデマンド |
| データ | API（二次データ含む） | 決算資料・開示書類などの一次情報 |
| 出力 | 候補リスト＋通過理由 | スコア、目標株価、期待倍率、Kill 条件 |
| 判断 | しない | する |

## 設計ルール

1. **スクリーナーの数値は「手がかり」扱い。** 評価スキル側で一次情報から取り直す。両者の乖離が大きい場合はフラグとして扱う。
2. **足切り条件はスクリーナーに一本化。** 時価総額レンジ等の絶対条件はスクリーナーで持ち、評価スキルは「通過済み」を前提にする。
3. **指標選択ルールを揃える。** 評価スキルの margin stage 切替（営業利益率 < −20% は PSR、損益分岐付近は EV/粗利、> 15% は EV/EBIT）をスクリーナーの割安判定にも使う。
4. **期待倍率・スコアはスクリーナーで出さない。** 近似値が判断に流用されるのを防ぐ。

## 連携フロー

```
スクリーニング（週次・全銘柄）
  → 簡易評価（評価スキルの簡潔モード、20〜30件 → 5〜10件）
  → 本評価（評価スキル詳細モード）
```

### トラックA/B でスコアの出方が違う

トラックA候補は、評価スキルの①成長性で構造的に低く出る（3年CAGR 10% の合格ラインが①では3〜4点の帯）。
簡易評価で絞り込むときは、**トラックごとに比べる**。総合スコアを一列に並べると、トラックA候補が理由なく下位に固まる。
経緯と据え置いた理由は `docs/screening-criteria.md` の②。

### 評価スキルの5軸のうち、スクリーナーが見ていないもの（2026-09-23 決定）

評価スキルの `references/scorecard.md` は5軸を固定の加重で合成する。スクリーナーの条件との対応はこうなっている（#54）。

| 軸 | 加重 | スクリーナー側 |
|---|---|---|
| ① 成長性 | 0.20 | `revenue_cagr_3y`, `revenue_growth_yoy` |
| ② 収益性 | 0.20 | `op_margin`, `gross_margin`, `roa` / `roe` |
| ③ モート | 0.20 | **足切りなし。** CSV に参考値 `gross_margin_change_3y` を載せる |
| ④ バリュエーション | 0.30 | `fcf_yield`, `pbr`, `psr` |
| ⑤ カタリスト・可視性 | 0.10 | **扱わない** |

**③と⑤（合計0.30）はスクリーナーでは落とさない。** 評価スキルにかけて初めて低く出る銘柄が候補に残ることは仕様である。
総合8.0に届くには事業側（①②③⑤の加重平均）が7.15以上要る（`0.3×10 + 0.7×7.143 = 8.0`）が、
スクリーナーではそれを判定しない。

- **③モート：参考値だけ出す。** ルーブリックが数値の裏付けに挙げているのは「粗利率の維持 / 低下」だけで、
  残りは10-K Item 1 等を読む定性評価。`gross_margin_change_3y` は直近年度と3年前の粗利率の差（率の差。−0.05 は −5pt）で、
  どちらかの年度で粗利が取れなければ空欄。足切りにしない理由：
  - 粗利率は事業構成の変化でも動き、競争による値崩れと区別できない。2026-09-21 の run で最も下がった
    TMDX（−9.9pt）は、低採算の航空輸送事業が伸びたことによるものと見られる（10-K での裏取りはしていない）
  - 粗利率の**推移**が多倍株を予測するという研究の裏付けが無い（Novy-Marx の粗利益/総資産は水準の指標）。閾値を置けば見解になる
  - `screen_results` には持たない。判定に使った値を残すテーブルで、参考値は `fundamentals` から計算し直せる
- **⑤カタリスト：扱わない。** ルーブリックの数値材料は受注残・RPO だが、`RevenueRemainingPerformanceObligation` を
  2024年6月以降に報告しているのはユニバースの22.6%（3,184社中718社、2026-09-19 の companyfacts）。
  契約負債（`ContractWithCustomerLiability*`）は取れる企業が多いが、小売のギフトカードや預り金を含み、来期売上の可視性の代わりにならない。
  8割が空欄の列は「可視性が無い」と誤読されるので載せない。RPO は評価スキルが10-K から取り直す（設計ルール1）

## 追加で担う役割

- **Kill 条件の監視。** 評価スキルが観測可能な指標（売上成長率、利益率など）で定義した Kill 条件を、保有・ウォッチ銘柄について週次で自動チェックする。
- **フィードバック。** 評価スキルの判定結果を記録し、どの通過条件が高スコアにつながったかを蓄積して閾値調整に使う。

## インターフェース

- スクリーナーは独立ツールとして実装（評価スキルに組み込まない）。
- 評価スキル側には「スクリーナー出力（CSV）を受け取る」入口だけを追加する。
- 出力 CSV の想定列（たたき台）：`ticker, market, name, track(A/B), passed_filters, timing_score, market_cap, revenue_cagr_3y, op_margin, fcf_yield, pbr, psr, range_position_52w, data_source, as_of`
  - 実装ではこれに、判定に使った全指標・参考値（`gross_margin_change_3y`）・出典と基準日を足してある（`src/stock_radar/output/csv_writer.py`）
