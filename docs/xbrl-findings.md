## A. 年次レコードの選定ルール

### A-1. `fy` / `fp` は「報告した提出書類」の会計年度であって、データの期間ではない

**サンプル全体で 66%（648/977 エントリ）で `fy` が期間末の年と一致しなかった。**

Apple の例。同じ FY2022（2021-09-26〜2022-09-24）のデータが `fy=2023` と `fy=2024` の両方で出る。

```
2021-09-26..2022-09-24  364日  394,328,000,000  fy=2023 fp=FY filed=2023-11-03
2021-09-26..2022-09-24  364日  394,328,000,000  fy=2024 fp=FY filed=2024-11-01
```

→ **決定：年次レコードは `fy` ではなく `start` / `end` で束ねる。** `fy` は使わない。

### A-2. 同じ期間が1〜5回出る

| 同一期間のエントリ数 | 期間数 |
|---|---|
| 1回 | 104 |
| 2回 | 91 |
| 3回 | 211 |
| 4回 | 12 |
| 5回 | 2 |

元の 10-K に加えて、翌年・翌々年の 10-K の比較欄で再掲されるため。3回が最頻。

### A-3. 修正再提出で値が変わることは実在する

サンプル20社で **55 件**。振れ幅は2種類に分かれた。

| 例 | 変化 |
|---|---|
| AAPL `SalesRevenueNet` FY2009 | 36,537M → 42,905M（**+17.4%**） |
| WMT `Revenues` FY2013 | 468,651M → 469,162M（+0.11%） |

Apple の大きい方は iPhone の収益認識変更（2010年の遡及修正）。
小さい方は表示区分の組み替え。

→ **決定：同じ期間に複数エントリがあるときは `filed` が最新のものを採る。**
「当時報告された値」ではなく「最新の値」を使う。理由は成長率の一貫性で、
3年CAGR を古い基準と新しい基準の混在で計算すると、実態のない成長・減少が出る。
採用した `accn` と `filed` は `fundamentals` に残すので、後から当時の値には戻れる。

### A-4. 期間長は 364 / 365 / 366 / 371 日

10-K に載る売上エントリの期間長（サンプル20社、絞り込みなし）。

| 期間長 | 件数 | |
|---|---|---|
| 62〜98日 | 985 | 四半期（10-K の中にも載る） |
| 184日 | 5 | 半期 |
| 364日 | 198 | 52週決算 |
| 365日 | 547 | |
| 366日 | 189 | 閏年 |
| 371日 | 43 | 53週決算 |

→ **決定：`end - start + 1` が 350〜380日のものだけを年次として扱う。**
設計時に置いた 350〜380 のガードは実測でも妥当だった。**フォームが 10-K かどうかだけでは足りない**
（10-K の中に四半期・半期のエントリが載っている）。

### A-5. 10-K の中の9ヶ月データは決算期変更ではない

母集団のうち **226社**の 10-K に 200〜350日の期間が載っていた。当初これを決算期変更と誤認したが、
中身は比較用の中間期データ（例：IFF の 2024-01-01..2024-09-30）だった。
**350〜380日ガードが正しく除外する。**

本物の決算期変更は **10-KT（移行報告）** で見分ける。母集団の売上エントリでの内訳：

| フォーム | エントリ数 |
|---|---|
| 10-K | 194,791 |
| 10-K/A | 4,269 |
| **10-KT** | **397** |
| 10-KT/A | 6 |

### A-6. ⚠️ 同じ年度が数日ずれた期末で二重に出る（19社）

**設計時に想定していなかったケース。**

```
cik=315189 (DEERE)  2015-10-31 → 2015-11-01  間隔 1日
cik=315189 (DEERE)  2016-10-30 → 2016-10-31  間隔 1日
```

同じ会計年度を、提出書類によって1日違う期末で報告している。
`end` の文字列をそのままキーにすると **1つの年度が2行になり、3年CAGR が1年ずれる。**

→ **決定：年次レコードは期末日そのものではなく、数日の揺れを吸収した会計年度で束ねる。**
実装では「直前に採用した期末から340日未満のエントリは同一年度とみなし、`filed` が新しい方を採る」。

### A-9. ⚠️ 同じ提出書類が同じ期末を2回報告し、値が4倍違うことがある

**Phase 2b の取り込みで見つかった。設計時にもA〜Dの調査でも想定していなかった。**

同じ `(cik, concept, unit, period_end, accn)` に対してエントリが2つ出ることがある。
違うのは `period_start` だけ。母集団での件数は年次104件・四半期61件、**うち14件は値が食い違う。**

```
Coeur Mining 2011年度（同じ 10-K、同じ accn）
  2011-01-01 .. 2011-12-31  365日  1,021,200,000
  2011-01-10 .. 2011-12-31  356日    246,911,000   ← 4倍違う
```

**どちらも 350〜380日のガードを通る。** 期間長だけでは選べない。

→ **決定：縦持ちテーブルには両方入れる**（一意制約を付けない）。
正規化では、**同じ期末を共有する期間が複数あれば期間長が最も1年に近いものを採る。**

### A-7. 年次期間の間隔（母集団 3,184社）

| 間隔 | 件数 | 意味 |
|---|---|---|
| 1〜14日 | 29 | A-6 の二重計上（19社） |
| 15〜339日 | 115 | 決算期の短縮 |
| 391〜750日 | 163 | 決算期の延長、または1年分の欠落 |
| 751日以上 | 80 | 履歴の断絶 |

→ **決定：3年CAGR は「3行前」ではなく「期末が約3年前（1,000〜1,190日）の年度」で計算する。**
行数で数えると、履歴に穴がある企業で year の数が合わない。条件を満たす年度が無ければ CAGR は欠損とする。

### A-8. BS 項目に `start` は付かない

`Assets` のエントリ **2,383件すべて**が `end` のみだった。

→ **決定：`start` の有無で時点値（BS）と期間値（PL/CF）を機械的に区別する。**

## B. 四半期の YTD → 3ヶ月変換

### 結論：⚠️ **設計の前提が実データと違った。変換はほぼ不要。**

設計（`docs/architecture.md`）は「多くの企業は YTD でしか報告しない」と書いていたが、
**米国 XBRL では3ヶ月値が直接報告されている。**

サンプル20社の 10-Q 売上エントリ：

| 期間長 | 件数 |
|---|---|
| 3ヶ月 | 1,715 |
| 6ヶ月（YTD Q2） | 576 |
| 9ヶ月（YTD Q3） | 559 |

`fp` との対応：

| `fp` | 3ヶ月 | YTD |
|---|---|---|
| Q1 | 560 | —（Q1 は YTD = 3ヶ月） |
| Q2 | 582 | 576 |
| Q3 | 571 | 559 |

**3ヶ月値と YTD が併記されている。** サンプルで 10-Q を出す19社すべてが3ヶ月値を持っていた
（SHPH のみ売上エントリ自体が無い）。

母集団 3,184社での実測：**2,943社（92.4%）が3ヶ月値を直接持つ。**

→ **決定：四半期は期間長 80〜100日のエントリを直接採る。YTD の引き算はしない。**
取れない 7.6% は `revenue_growth_latest_quarter_yoy` を欠損として扱う
（トラックB のこの条件は判定不能になる）。

### Q4 について

Q4 単独の3ヶ月値は 10-K の中に載っている企業が多い（サンプル20社中12社）。
ただし **トラックB が使うのは「直近四半期の前年同期比」だけ**で、年度をまたぐ積み上げには使わない。
Q4 を導出する必要は無いので、`通期 − YTD(Q3)` の実装は不要。

## C. 複数クラス株の株数

### 結論：⚠️ **仮説は当たり。`companyfacts` に軸（dimension）付きファクトは含まれない。**

Alphabet の全エントリに現れるキーを列挙したところ、
`accn / end / filed / form / fp / frame / fy / start / val` のみで、
**軸を表すキーは1つも無かった。**

その結果、株式クラスごとに開示している企業では
`dei:EntityCommonStockSharesOutstanding` が**丸ごと欠落する**。

| 企業 | `dei:EntityCommonStockSharesOutstanding` |
|---|---|
| GOOGL（3クラス） | **エントリなし** |
| RDDT（2クラス） | **エントリなし** |
| FNKO（2クラス） | **エントリなし** |
| BRK（2クラス） | 7件のみ（極端に疎） |
| AAPL（単一クラス） | 70件 |

母集団での出現率も **90.8%** にとどまる。

### 代替：軸なしの全クラス合計が別タグで取れる

| タグ | 出現率 | GOOGL の値 |
|---|---|---|
| `us-gaap:WeightedAverageNumberOfSharesOutstandingBasic` | **97.6%** | 12,125,000,000 |
| `us-gaap:WeightedAverageNumberOfDilutedSharesOutstanding` | **97.4%** | 12,274,000,000 |
| `dei:EntityCommonStockSharesOutstanding` | 90.8% | （なし） |
| `us-gaap:CommonStockSharesIssued` | 89.5% | 12,230,000,000 |
| `us-gaap:CommonStockSharesOutstanding` | 85.4% | 12,230,000,000 |

Alphabet の全クラス合計は約12.2億×10 = 約122億株で、いずれも合計値になっている。

→ **決定：`WeightedAverageNumberOfDilutedSharesOutstanding` を第1候補にする。**
`dei:EntityCommonStockSharesOutstanding` は3番目に落とす。優先順位は `concepts.py` に記載。

### 残る不正確さ（近似で済ませ、フラグを立てる）

- **期中平均であって期末の実数ではない。** 増資・自社株買いの直後はずれる
- **クラスごとに株価が違う。** 全クラス合計 × 片方の株価は厳密には誤り。
  GOOG と GOOGL は1%以内なので実害は小さいが、BRK.A / BRK.B は1,500倍違う（BRK は金融で除外済み）

### 実測：yfinance の `marketCap` と照合した（2026-09-21、10銘柄）

| 銘柄 | 自前計算 | yfinance | 乖離 |
|---|---|---|---|
| GOOG | 4,212,134,344,788 | 4,212,111,966,208 | +0.0% |
| GOOGL | 4,274,874,304,504 | 4,274,851,676,160 | +0.0% |
| MSFT | 3,680,142,330,902 | 3,666,585,845,760 | +0.4% |
| NVDA | 5,448,726,884,735 | 5,367,153,557,504 | +1.5% |
| AAPL | 5,043,528,875,875 | 4,905,541,566,464 | +2.8% |
| VMI | 9,462,897,972 | 9,162,858,496 | +3.3% |

**乖離10%超は0/10。複数クラス株（GOOG / GOOGL）でも 0.0%** で、
「全クラス合計株数 × 片方の株価」という近似は実用に足りる。

わずかな上振れは**期中平均株式数を使っているため**。自社株買いをしている企業では
期末の実数より多くなる（AAPL の +2.8% がこれ）。桁を見る用途には影響しない。

→ **決定：時価総額は「全クラス合計株数 × 取得した株価」で近似する。**
複数クラス株の銘柄には CSV にフラグを立て、評価スキル側で気づけるようにする。
厳密なクラス別株数が要るなら `submissions` の表紙情報を読む別ルートが必要だが、第一弾ではやらない。

**粗利率が単独ブロッカーの筆頭**（トラックB の 15.5%）で、次が**トラックA の売上3年CAGR**（7.2%）。

### ⚠️ 実装してみると E の数字より厳しくなる（Phase 2b-3 で判明）

E は調査スクリプトによる概算で、「**いずれかの年度**にデータがあるか」で測っていた。
実装は「**直近年度で実際に計算できるか**」で判定するので、こちらの方が正しく、かつ厳しい。

| 指標 | E（調査） | 実装 |
|---|---|---|
| 売上3年CAGR | 82.8% | 78.7% |
| 売上YoY（年次） | 90.1% | 85.6% |
| 直近四半期YoY | 89.3% | 87.4% |
| 営業利益率 | 88.0% | 81.3% |
| 粗利率 | 74.1% | 63.8% |
| FCF | 92.9% | 85.1% |
| **資産成長率 − EBIT成長率** | **92.7%** | **46.0%** |
| トラックA を判定できる | 77.4% | **39.1%** |
| トラックB を判定できる | 69.5% | **59.1%** |

**「資産成長率 − EBIT成長率」だけ落ち方が桁違い。** 理由は定義の問題で、
**前期の営業利益が赤字だと EBIT成長率を定義できない**（母集団の 44.9%）。
`-80 / -70 - 1 = +14%` と出すと、赤字が拡大したのに成長したことになる。

ただし**トラックA は当期の営業黒字を求める**ので、実際に影響を受けるのは
**前期赤字から黒字転換した165社**だけ。残りの1,255社は営業利益率の条件で
どのみち落ちる。

→ 指標側は正直に `None` を返し、**`ebit_turned_positive` を別に持たせた。**
条件の趣旨（資産を膨らませているのに収益が伴わない企業を外す）からは黒字転換を
通すべきに見えるが、**判定に使うかは Phase 4 で決める**（要ユーザー確認）。

### 欠測の性質は2種類あり、扱いを分けるべき

| | 例 | 性質 | 落としてよいか |
|---|---|---|---|
| **事実として存在しない** | 売上3年CAGR（IPO直後で履歴が無い） | データの問題ではなく、条件が前提とする実体が無い | **落としてよい。** Yartseva の条件は履歴を前提にしている |
| **実体はあるが開示形式で取れない** | 粗利率（航空・電力が粗利の行を持たない） | 経済実態はあるのに測れないだけ | **落とすと情報を失う。判断が要る** |

## 🔴 スクリーニング条件の見直し提案（G1）

### F. 粗利条件をスキップすると実際に何社増えるか

「判定不能を落とす」ことの本当のコストを測った。粗利が算出できず、
かつトラックB の他の**財務**条件（売上YoY 25%以上 / 直近四半期YoY 20%以上 /
営業利益率 −20%以上 / 自己資本比率50%または流動比率1.5）を当てられる445社について、
実際に判定した。

| | 社数 |
|---|---|
| 粗利以外の条件で落ちる | 422（94.8%） |
| **粗利以外の条件を通る** | **23（5.2%）** |

→ **粗利条件をスキップしても、トラックB に増えるのは最大23社。**
PSR と時価総額をまだ当てていないので、これは上限値であり実際はさらに減る。

増える23社の業種は石油・ガス5 / 医薬・バイオ7 / 事業サービス4 / ソフトウェア2 / その他5。
**粗利率40%という条件が外そうとしている低採算業態そのもの**で、
取りこぼしとして惜しい構成にはなっていない。

比較：粗利が取れる2,203社のうち、他の財務条件を通るのは98社。

### 提案：`track_b.gross_margin` はハードフィルタのまま残す（＝粗利不明の銘柄は落とす）

**変更不要と考える。** 理由：

1. **スキップしても増えるのは最大23社**（上記 F の実測）。しかもその内訳は
   粗利率40%が外そうとしている業態そのもの
2. 粗利を開示しない業態（電力・航空・飲食・ホテル・石油）は、そもそも粗利率40%を満たさない。
   判定不能で落ちても、判定できていても結果は同じ
3. 一方でスキップを許すと、**低採算の業態がトラックB に無条件で入れるようになる**。
   トラックB は「高粗利でスケールする事業モデル」を狙う枠なので、趣旨が崩れる

ただし **「粗利不明で判定不能」と「粗利率が閾値未満」を区別して記録する。**
`screen_results` に理由を残し、CSV でも見えるようにする。これが無いと、
取りこぼしが起きていること自体に気づけない。

## G. 3年CAGR が計算できない企業はトラックB で拾えるか

「IPO 直後の高成長企業はトラックB（年次YoY と四半期YoY）で拾えるはず」という仮説を検証した。

対象は**売上はあるが3年CAGR が計算できない 279社**
（E の「判定不能 549社」から、売上そのものが無い270社を除いたもの）。

| 行き先 | 社数 |
|---|---|
| **★トラックB の財務条件を通る** | **4** |
| トラックB は判定できたが条件で落ちる | 109 |
| トラックB も判定不能（売上・営業利益が足りない） | 76 |
| トラックB も判定不能（粗利が出ない） | 55 |
| トラックB も判定不能（四半期が足りない） | 25 |
| トラックB も判定不能（前年度が揃わない） | 10 |

落ちた条件の内訳（重複あり）：営業利益率 78 / 売上YoY 59 / 四半期YoY 56 / 粗利率 55 / 財務バッファ 41。

### ⚠️ 仮説は外れ。ただし結論は変わらない

**トラックB は受け皿として機能していない（279社中4社）。**
「トラックA で落ちてもトラックB が拾う」という想定は成り立たない。

それでも3年CAGR を必須のまま残してよい理由は別にある。

- **109社は判定できたうえで条件に届いていない。** 落とすべき企業が落ちている
- **101社（76 + 25）は上場から日が浅く、前年度も四半期履歴も揃わない。**
  どの条件でも評価できない。これはデータの問題ではなく、判断材料が存在しないということ
- 55社は粗利の問題で、上記の案1 で決着済み

### 🔵 決定（2026-09-21 ユーザー判断）：**3年CAGR は必須のまま**

履歴が事実として存在しない企業を落とすのは正しい。
ただし**トラックB が受け皿にならないことは記録しておく** — 「上場3年未満の高成長企業は
第一弾のスクリーナーでは拾えない」という既知の穴であり、第一弾より後の検討事項にする。
